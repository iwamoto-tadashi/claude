文字コード判定

あなた#01

c#でstreamから文字コードを判定する関数を作成してください

Claude

日本語の文書処理（CSVアップロードなど）でよく使う、BOM判定＋ヒューリスティックによる文字コード判定関数を作成します。外部ライブラリなしで実装し、UTF-8 / Shift-JIS(CP932) / EUC-JP / UTF-16(BOM) を判定できるようにします。

ファイル作成 ・ EncodingDetector.cs（この時点では .NET Core/5+ 向けで CodePagesEncodingProvider を登録）

使い方はこんな感じです。

using (var fs = File.OpenRead(@"C:\path\to\file.csv"))
{
    Encoding encoding = EncodingDetector.DetectEncoding(fs);
    Console.WriteLine(encoding.WebName); // shift_jis, utf-8, euc-jp など

    fs.Position = 0;
    using var reader = new StreamReader(fs, encoding);
    string content = reader.ReadToEnd();
}

判定ロジックのポイント

  1. BOM判定を最優先。UTF-8/UTF-16(LE/BE)/UTF-32のBOMがあれば即座に確定します。
  2. BOMが無い場合はバイトパターンの妥当性チェック。UTF-8として不正な並びがないか厳密に検証し、次にEUC-JP、最後にShift-JIS(CP932)の順で判定します。Shift-JISの2バイト目の許容範囲が広く誤検知しやすいため、この順序にしています。
  3. 判定不能な場合はShift-JISにフォールバック。日本語の業務システムではShift-JISが既定のことが多いための実務的な選択です。

注意点・制約

  • ヒューリスティック判定なので、短い文字列や特定のバイト列では誤判定の可能性があります。ASCII文字のみのファイルはUTF-8扱いにフォールバックする設計です。
  • より高精度な判定が必要なら、Ude.NetStandard（Mozilla Universal Charset Detector の.NET移植）のNuGetパッケージも検討する価値があります。
  • .NET Core/5+ では CodePagesEncodingProvider の登録が必要なため、静的コンストラクタで登録しています。

CSVアップロード機能などで使う想定でしょうか？もしその用途なら、StreamReaderとの組み合わせ部分や、判定失敗時のエラー表示なども含めて調整できます。

using System;
using System.IO;
using System.Text;

namespace CommonUtils.Utility
{
    /// <summary>
    /// ストリームから文字コードを判定するユーティリティ。
    /// 1. BOM (UTF-8 / UTF-16LE / UTF-16BE / UTF-32) をチェック
    /// 2. BOM が無い場合はバイト列のパターンから UTF-8 / Shift-JIS(CP932) / EUC-JP を推定
    /// 外部ライブラリ不要。ただし精度が重要な場合は Ude.NetStandard 等の
    /// Mozilla Universal Charset Detector 系ライブラリの利用も検討してください。
    /// </summary>
    public static class EncodingDetector
    {
        // .NET Frameworkでは Shift-JIS / EUC-JP 等のコードページは標準で
        // 利用可能なため、CodePagesEncodingProvider の登録は不要です。
        // （.NET Core/5+ に移植する場合は System.Text.Encoding.CodePages を参照し、
        //   Encoding.RegisterProvider(CodePagesEncodingProvider.Instance) を
        //   アプリ起動時に一度呼び出してください）

        /// <summary>
        /// ストリームの内容から文字コードを判定します。
        /// 呼び出し後、stream の位置は先頭(Position = 0)に戻されます（Seek可能な場合）。
        /// </summary>
        /// <param name="stream">判定対象のストリーム（Seek可能である必要があります）</param>
        /// <param name="sampleSize">判定に使用する先頭バイト数（既定 32KB）</param>
        public static Encoding DetectEncoding(Stream stream, int sampleSize = 32 * 1024)
        {
            if (stream == null) throw new ArgumentNullException(nameof(stream));
            if (!stream.CanSeek) throw new ArgumentException("Seek可能なストリームを指定してください。", nameof(stream));

            long originalPosition = stream.Position;
            stream.Position = 0;

            try
            {
                int lengthToRead = (int)Math.Min(sampleSize, stream.Length);
                byte[] buffer = new byte[lengthToRead];
                int readBytes = 0;
                while (readBytes < lengthToRead)
                {
                    int n = stream.Read(buffer, readBytes, lengthToRead - readBytes);
                    if (n == 0) break;
                    readBytes += n;
                }
                if (readBytes < buffer.Length)
                {
                    Array.Resize(ref buffer, readBytes);
                }

                return DetectEncoding(buffer);
            }
            finally
            {
                stream.Position = originalPosition;
            }
        }

        /// <summary>
        /// バイト配列から文字コードを判定します。
        /// </summary>
        public static Encoding DetectEncoding(byte[] bytes)
        {
            if (bytes == null || bytes.Length == 0)
            {
                return Encoding.UTF8; // データが無い場合の既定値
            }

            // --- 1. BOM 判定 ---
            var bomEncoding = DetectByBom(bytes);
            if (bomEncoding != null)
            {
                return bomEncoding;
            }

            // --- 2. BOM無し: バイトパターンによるヒューリスティック判定 ---
            if (IsValidUtf8(bytes))
            {
                // 有効なUTF-8バイト列（かつ日本語特有のマルチバイトパターンが
                // Shift-JIS/EUC-JPとして偶然成立する可能性は低いため信頼度が高い）
                return new UTF8Encoding(false);
            }

            if (IsValidEucJp(bytes))
            {
                return Encoding.GetEncoding("euc-jp");
            }

            if (IsValidShiftJis(bytes))
            {
                return Encoding.GetEncoding("shift_jis"); // CP932
            }

            // どれにも当てはまらない場合はフォールバック
            // 日本語業務システムでは Shift-JIS が既定であることが多い
            return Encoding.GetEncoding("shift_jis");
        }

        private static Encoding DetectByBom(byte[] bytes)
        {
            if (bytes.Length >= 4 &&
                bytes[0] == 0x00 && bytes[1] == 0x00 && bytes[2] == 0xFE && bytes[3] == 0xFF)
            {
                return new UTF32Encoding(true, true); // UTF-32 BE
            }
            if (bytes.Length >= 4 &&
                bytes[0] == 0xFF && bytes[1] == 0xFE && bytes[2] == 0x00 && bytes[3] == 0x00)
            {
                return new UTF32Encoding(false, true); // UTF-32 LE
            }
            if (bytes.Length >= 3 &&
                bytes[0] == 0xEF && bytes[1] == 0xBB && bytes[2] == 0xBF)
            {
                return new UTF8Encoding(true); // UTF-8 with BOM
            }
            if (bytes.Length >= 2 &&
                bytes[0] == 0xFE && bytes[1] == 0xFF)
            {
                return new UnicodeEncoding(true, true); // UTF-16 BE
            }
            if (bytes.Length >= 2 &&
                bytes[0] == 0xFF && bytes[1] == 0xFE)
            {
                return new UnicodeEncoding(false, true); // UTF-16 LE
            }
            return null;
        }

        /// <summary>
        /// バイト列が正しいUTF-8として解釈可能かどうかを厳密にチェックします。
        /// </summary>
        private static bool IsValidUtf8(byte[] bytes)
        {
            int i = 0;
            bool hasMultiByte = false;

            while (i < bytes.Length)
            {
                byte b = bytes[i];

                if (b <= 0x7F)
                {
                    i += 1;
                }
                else if ((b & 0xE0) == 0xC0) // 110xxxxx : 2バイト文字
                {
                    if (!HasContinuationBytes(bytes, i, 1)) return false;
                    hasMultiByte = true;
                    i += 2;
                }
                else if ((b & 0xF0) == 0xE0) // 1110xxxx : 3バイト文字
                {
                    if (!HasContinuationBytes(bytes, i, 2)) return false;
                    hasMultiByte = true;
                    i += 3;
                }
                else if ((b & 0xF8) == 0xF0) // 11110xxx : 4バイト文字
                {
                    if (!HasContinuationBytes(bytes, i, 3)) return false;
                    hasMultiByte = true;
                    i += 4;
                }
                else
                {
                    return false; // 不正な先頭バイト
                }
            }

            // ASCIIのみの場合、UTF-8/Shift-JIS/EUC-JP のいずれとしても正当なため、
            // 誤検知を避けるためここでは「多バイト文字を含む場合のみ」UTF-8と積極判定する。
            // 呼び出し側の判定順序（UTF-8→EUC-JP→Shift-JIS）と組み合わせて使用してください。
            return hasMultiByte || IsAsciiOnly(bytes);
        }

        private static bool HasContinuationBytes(byte[] bytes, int start, int continuationCount)
        {
            if (start + continuationCount >= bytes.Length) return false;
            for (int j = 1; j <= continuationCount; j++)
            {
                if ((bytes[start + j] & 0xC0) != 0x80) return false; // 10xxxxxx でなければ不正
            }
            return true;
        }

        private static bool IsAsciiOnly(byte[] bytes)
        {
            foreach (var b in bytes)
            {
                if (b > 0x7F) return false;
            }
            return true;
        }

        /// <summary>
        /// Shift-JIS(CP932)として妥当なバイト列かどうかをヒューリスティックにチェックします。
        /// </summary>
        private static bool IsValidShiftJis(byte[] bytes)
        {
            int i = 0;
            while (i < bytes.Length)
            {
                byte b = bytes[i];

                if (b <= 0x7F || b == 0xA5 || b == 0x80 || (b >= 0xA1 && b <= 0xDF))
                {
                    // ASCII、半角カナ等の1バイト文字
                    i += 1;
                }
                else if ((b >= 0x81 && b <= 0x9F) || (b >= 0xE0 && b <= 0xFC))
                {
                    // 2バイト文字の先頭バイト
                    if (i + 1 >= bytes.Length) return false;
                    byte b2 = bytes[i + 1];
                    bool validSecondByte =
                        (b2 >= 0x40 && b2 <= 0x7E) || (b2 >= 0x80 && b2 <= 0xFC);
                    if (!validSecondByte) return false;
                    i += 2;
                }
                else
                {
                    return false;
                }
            }
            return true;
        }

        /// <summary>
        /// EUC-JPとして妥当なバイト列かどうかをヒューリスティックにチェックします。
        /// </summary>
        private static bool IsValidEucJp(byte[] bytes)
        {
            int i = 0;
            bool hasMultiByte = false;

            while (i < bytes.Length)
            {
                byte b = bytes[i];

                if (b <= 0x7F)
                {
                    i += 1;
                }
                else if (b == 0x8E) // 半角カナ (SS2)
                {
                    if (i + 1 >= bytes.Length) return false;
                    byte b2 = bytes[i + 1];
                    if (b2 < 0xA1 || b2 > 0xDF) return false;
                    hasMultiByte = true;
                    i += 2;
                }
                else if (b == 0x8F) // JIS X 0212 (SS3)
                {
                    if (i + 2 >= bytes.Length) return false;
                    byte b2 = bytes[i + 1];
                    byte b3 = bytes[i + 2];
                    if (b2 < 0xA1 || b2 > 0xFE || b3 < 0xA1 || b3 > 0xFE) return false;
                    hasMultiByte = true;
                    i += 3;
                }
                else if (b >= 0xA1 && b <= 0xFE) // 通常の2バイト文字
                {
                    if (i + 1 >= bytes.Length) return false;
                    byte b2 = bytes[i + 1];
                    if (b2 < 0xA1 || b2 > 0xFE) return false;
                    hasMultiByte = true;
                    i += 2;
                }
                else
                {
                    return false;
                }
            }

            return hasMultiByte; // ASCIIのみの場合はUTF-8判定に譲る
        }
    }
}

あなた#04

Ude.NetStandardは商用利用しても大丈夫ですか？

Claude

Web検索 ・ Ude.NetStandard のライセンスを確認

はい、商用利用は可能ですが、ライセンス形態が少し特殊なので整理します。

ライセンス

Ude.NetStandard は errepi/ude（Mozilla Universal Charset Detectorの移植版）をベースにしており、MPL 1.1、またはGPL v2以降、あるいはLGPL v2.1以降のいずれかで利用できるトリプルライセンスです。

商用利用について

MPL・GPL・LGPLはいずれも商用利用OKです。ただしコピーレフト系なので注意点があります。

  • MPL 1.1を選択した場合：ライブラリのソースコードを改変した場合、改変部分はMPLのまま公開する必要があります（ファイル単位の弱いコピーレフト）。改変せずバイナリ参照するだけなら、自社システム全体をMPLにする必要はありません。
  • GPL/LGPLを選択した場合：GPLは強いコピーレフトなので、リンクする自社コード全体に影響する可能性があります。LGPLなら、動的リンク（NuGetパッケージとして参照するだけ）であれば自社コードへの影響は限定的です。

実務上の結論

  • NuGetパッケージとして参照し、ソースコードを改変せずに使うだけなら、社内の年末調整システムに組み込んでも実質的な問題は生じにくいです（ソースを配布するわけではないため）。
  • 外部に配布・販売する場合や、コンプライアンス上ライセンス条件を厳密に確認する必要がある場合は、法務部門やライセンス管理担当への確認をお勧めします。

代替として UTF.Unknown（CharsetDetector/UTF-unknown）という後継的なライブラリもあります。採用する場合はそちらのLICENSEファイルも確認してください。社内ポリシー上OSSの導入が難しいなら、外部依存なしの EncodingDetector をそのまま使う方が手軽かもしれません。

あなた#05

年末調整システムはazureで公開するサービスで、元のコードは改修しない予定です。どちらを選ぶのが無難ですか？

Claude

今回の状況（Azure上で公開する自社サービス、ライブラリのソース改変なし）を踏まえると、ライセンスリスクの観点では Ude.NetStandardを使っても問題は小さい と考えられます。

ライセンスリスクが低い理由

  • MPL・GPL・LGPLはいずれも「配布（distribution）」時に義務が発生するライセンスです。
  • Azure上でサービスとして稼働させ、Webアプリとして提供する形態は、一般的にソフトウェアの配布に該当しません。
  • 例外はAGPL（ネットワーク条項を持つ）ですが、Ude.NetStandardはMPL/GPL/LGPLの三択でAGPLではありません。
  • ソースコードを改変しないので、MPL特有の改変ファイル公開義務も発生しません。

どちらを選ぶか

ライセンスリスクがほぼ同等なら、判断基準は精度と保守性に移ります。

Ude.NetStandard自作EncodingDetector
判定精度高い（Mozilla発の実績あるアルゴリズム、28種の文字コードに対応）中程度（ヒューリスティック、限定的な文字コードのみ）
依存関係外部NuGetパッケージが増える追加依存なし
保守性ライブラリ側で継続的に検証済み自社でロジックを保守する必要あり
最終更新2019年頃で更新停止気味（後継のUTF.Unknownの方が活発）自社管理下

結論（無難な選択）

  • 社内のOSS利用ポリシーでMPL/GPL/LGPL系ライブラリの導入が許容されているなら、Ude.NetStandard（または UTF.Unknown）を採用して精度を優先するのが無難です。
  • OSSライセンスの審査プロセスが重い、または依存を増やしたくないなら、自作 EncodingDetector のまま運用し、カバーできていない文字コードが出たら個別対応します。

私は法律の専門家ではないため、一般的な整理です。最終判断は、御社のOSS利用ポリシーや法務・コンプライアンス部門に確認してください。

インストール

Install-Package UTF.Unknown

基本的な使い方

using UtfUnknown;

// ストリームから判定
DetectionResult result = CharsetDetector.DetectFromStream(stream);

DetectionDetail best = result.Detected;

if (best != null)
{
    string encodingName = best.EncodingName;      // 例: "SHIFT_JIS"
    Encoding encoding = best.Encoding;             // System.Text.Encoding（nullの場合あり）
    float confidence = best.Confidence;            // 0.0〜1.0の信頼度
}

ファイルパスから直接判定することもできます。

DetectionResult result = CharsetDetector.DetectFromFile("path/to/file.csv");

非同期版もあります。

DetectionResult result = await CharsetDetector.DetectFromFileAsync("path/to/file.csv", cancellationToken);

自作 EncodingDetector と置き換える場合のイメージ

using System.IO;
using System.Text;
using UtfUnknown;

namespace CommonUtils.Utility
{
    public static class EncodingDetector
    {
        public static Encoding DetectEncoding(Stream stream)
        {
            long originalPosition = stream.Position;
            stream.Position = 0;

            try
            {
                DetectionResult result = CharsetDetector.DetectFromStream(stream);
                DetectionDetail best = result?.Detected;

                if (best?.Encoding != null && best.Confidence >= 0.5f)
                {
                    return best.Encoding;
                }

                // 信頼度が低い、または判定失敗時のフォールバック
                return Encoding.GetEncoding("shift_jis");
            }
            finally
            {
                stream.Position = originalPosition;
            }
        }
    }
}

実務上のポイント

  • Confidence（信頼度）を必ずチェックする。日本語の短いテキストや空データでは信頼度が低く出ることがあるため、閾値（例: 0.5〜0.7）を設けてフォールバック処理を入れておくと安全です。
  • Encoding プロパティがnullの場合がある。一部のエンコーディングは.NETの標準 Encoding として取得できません。日本語の判定（Shift-JIS, EUC-JP, ISO-2022-JP, UTF-8）ではほぼ発生しません。
  • ストリームのPosition管理。DetectFromStream はストリームを内部で読み進めるため、判定後は Position = 0 に戻してください。
  • 依存関係。追加のNuGet依存はなく、DLLサイズも軽量です。

        /// </returns>
        public static Encoding DetectEncoding(Stream stream)
        {
            // ...
        }
    }

Service層とRepository層の設計

あなた#12

asp.net mvcでserviceレイヤーのクラスはcontroller単位で作成するのがいいですか？それとも機能単位がいいですか？

Claude

結論から言うと、機能（ドメイン）単位でのService作成をおすすめします。ただし例外もあります。

機能単位が有利な理由

  • ロジックの重複を防げる。同じ業務ロジックが複数のControllerから呼ばれることは業務システムでよくあります。Controller単位だと、同じ判定ロジックが画面ごとのServiceに重複しがちです。Q&A機能のように、管理者側と従業員側の両方のControllerから同じスレッド操作ロジックを呼ぶ構造は、機能単位Serviceが活きる典型例です。
  • ドメイン用語と一致させやすい。業務ドメインの概念に沿って KoujoService、HaigushaService のように切ると、税務知識を持つ人がコードを読んだときに「どこに何があるか」が理解しやすくなります。
  • テストしやすい。UIの都合に左右されない単体テストが書きやすくなります。

Controller単位が向いているケース

  • 各Controllerが独立した1機能に対応していて、ロジックを共有する見込みがほぼない場合（単純なCRUD画面など）
  • 小規模なアプリで、「どのControllerがどのServiceを使っているか」の対応の分かりやすさを優先したい場合
  • 開発初期でドメインの境界がまだ固まっていない場合

forstaffへの適用イメージ

  • KoujoService（各種控除計算：基礎控除・配偶者控除・扶養控除など）
  • HaigushaClassificationService（配偶者区分判定）
  • QuestionThreadService（Q&Aメッセージング、Admin/Employee両方から利用）
  • FileImportService（文字コード判定含むファイル取込処理）

Controller（EmployeeController, AdminController など）はこれらのServiceを組み合わせて画面固有のオーケストレーションだけを担当する、という役割分担にすると、UIの都合とビジネスロジックが分離されて見通しが良くなります。機能単位に切る際は、Serviceが肥大化したらさらに粒度を細かくする判断も必要です。

あなた#13

Service層で別のサービスに相互に呼び出す場合に気を付けることはありますか？

Claude

Service間の相互呼び出しは便利な反面、放っておくと保守性が一気に下がりやすい部分です。

1. 循環参照（相互依存）を避ける

ServiceAがServiceBを呼び、ServiceBもServiceAを呼ぶ構造は避けます。コンパイルは通っても、無限ループやDIの解決失敗を引き起こします。依存の方向を一方向に固定するレイヤールールを決めるのが対策です。双方向の連携が必要に見える場合は、共通ロジックが別に切り出されていないサインなので、第三のServiceに抽出して両方から参照します。

2. トランザクション・DbContextの扱い

EF6では、ServiceA→ServiceBと呼び出す際にそれぞれが別々の DbContext を持つと、片方だけ SaveChanges() が成功して整合性が崩れます。

  • 1リクエスト内で複数Serviceが同じデータ操作に関与する場合は、同じ DbContext インスタンスをDIで共有する（リクエスト単位）のが基本です。
  • 複数の SaveChanges() にまたがる操作をアトミックにしたい場合は、TransactionScope や Database.BeginTransaction() で明示的にトランザクション境界を作ります。
  • どちらが SaveChanges() を呼ぶ責任を持つかをルールとして決めておくと事故が減ります。

3. 責務の重複・境界の曖昧化

「このバリデーションはどっちのServiceの責任か」が曖昧になると、ロジックの二重管理になり、片方だけ改修して不整合が起きます。相手のServiceが何を保証するかを明確にし、同じ判定ロジックを自分でも実装し直さないことが重要です。

4. テストのしやすさが下がる

  • 各Serviceはインターフェース（IKoujoService など）越しに依存させ、モック差し替えを容易にします。
  • 1つのServiceが呼ぶ他Serviceの数が多くなりすぎたら（目安は4〜5個以上）、責務が大きすぎるサインとして分割を検討します。

5. パフォーマンス（N+1呼び出し）

一覧取得時に、スレッドごとに別Serviceを1件ずつ呼んでDBアクセスする実装だと、件数分のクエリが飛ぶN+1問題が発生します。Service間の呼び出しがループの中に入っていないかをレビューで確認します。

チェックリスト

  • 依存の方向は一方向か（循環していないか）
  • DbContext とトランザクション境界は誰が管理するか明確か
  • 同じ業務ルールを複数箇所で再実装していないか
  • モックの数が異常に増えていないか
  • ループの中でService呼び出し（＝DBアクセス）をしていないか
あなた#14

serviceがインスタンスを生成する必要がなければstatic classにする方がいいですか？

Claude

結論としては、Service層のクラスはインスタンスの生成が不要でも、staticクラスにしない方が無難です。

staticにすべきでない理由

  • DIコンテナで差し替え・モック化ができなくなる。staticクラスはインターフェースを実装できず、呼び出し側が KoujoService.Calculate(...) のように直接依存するため、テスト時に本物のロジックを必ず通ります。
  • DbContextやILoggerなどの依存を注入できない。今はDBアクセスがなくても、将来「マスタテーブルの参照が必要になった」という変更は業務システムでは頻繁に起こります。
  • 一貫性が崩れる。DI経由のインスタンスとstaticが混在すると、呼び出し方が統一されず、毎回コードを見て確認する手間が発生します。

staticが向いているケース

ビジネスロジックではなく、純粋なユーティリティ・ヘルパーであればstaticが適切です。判断基準は「DIコンテナで差し替えたくなる可能性があるか」「外部依存（DB、外部API、設定値）を持つ可能性があるか」です。EncodingDetector のようなクラスは、状態を持たない純粋な変換ロジックで、外部依存も発生しないため、staticのままで問題ありません。

種類staticでよいか理由
文字コード判定、日付フォーマット変換などの純粋関数○ static可外部依存なし、モック不要
控除計算、判定ロジックなどの業務Service✕ インスタンス化推奨将来のDB依存追加・テストのモック化に備える
他のServiceを呼び出すService✕ インスタンス化必須依存をコンストラクタ注入するため
あなた#15

管理画面専用のServiceがあり、そのServiceにビジネスロジックを集約してviewModelを返却する実装としています。DBへのアクセスはリポジトリ層に分離したほうがいいですか？

Claude

結論としては、「必ずRepository層を挟むべき」とは言い切れず、状況次第です。EF6の DbContext 自体がRepository/Unit of Workパターンに近い機能を提供しているため、追加のRepository層のメリットとコストを天秤にかける必要があります。

Repository層を追加するメリット

  • テストのしやすさ。EF6で DbContext を直接モックするのは面倒です。IKoujoRepository のようなインターフェースで抽象化すれば、Moqで簡単にモックできます。
  • クエリロジックの再利用・一元管理。似たLINQクエリが散らばるのを防げます。
  • EF6依存をServiceから隔離できる。ORMの移行や一部Dapper化の際の影響範囲が小さくなります。

Repository層を追加しないメリット

  • 不要な抽象化のオーバーヘッドを避けられる。GetById, GetAll だけの薄いRepositoryは「Repository over Repository」問題になりがちです。
  • LINQの表現力を活かしやすい。管理画面特有の複雑な絞り込み・集計は、Service内で直接LINQを書く方が柔軟です。

実務的な判断基準

  • そのServiceの単体テストを書く予定があるか。ある場合はRepository層をインターフェース経由で挟んだ方が書きやすくなります。
  • クエリが単純なCRUD中心か、複雑な集計・結合が多いか。
  • チーム内で既にRepositoryパターンの規約があるか。あるなら揃えた方が無難です。

折衷案：Query Objectとして切る

テスト容易性だけが目的なら、汎用的な IRepository<T> ではなく、その画面固有のクエリだけを小さなクラスに切り出す方法もあります。

public interface IUnsubmittedEmployeeQuery
{
    List<Employee> GetUnsubmittedEmployees(int year);
}

現在のServiceが具体的にどんなDBアクセス（単純なCRUDか、複雑な集計か）をしているか教えていただければ、より具体的に判断できます。

using CommonUtils.Extensions;
using manager.Models;
using System;
using System.Data;
using System.Data.SqlClient;

namespace manager.Repositories
{
    /// <inheritdoc cref="IHintTextBulkMergeRepository"/>
    public class HintTextBulkMergeRepository : IHintTextBulkMergeRepository
    {
        /// <inheritdoc/>
        /// <remarks>テーブルの構成が変われば BulkCopy、MergeSQLをメンテナンスしてください。</remarks>
        public int Merge(DataTable dt)
        {
            try
            {
                if (dt == null || dt.Rows.Count == 0)
                    return 0;

                using (var db = new dbModel())
                using (var tran = db.Database.BeginTransaction())
                {
                    try
                    {
                        // 一時テーブルに追加後にマージする
                        var sql = @"
                            drop table if exists #HintText;
                            select top 0 * into #HintText from HintText;
                            ";
                        db.Database.ExecuteSqlCommand(sql);

                        using (var bulk = new SqlBulkCopy(
                            db.Database.Connection as SqlConnection,
                            SqlBulkCopyOptions.Default,
                            db.Database.CurrentTransaction.UnderlyingTransaction as SqlTransaction))
                        {
                            bulk.DestinationTableName = "#HintText";
                            foreach (DataColumn col in dt.Columns)
                            {
                                bulk.ColumnMappings.Add(col.ColumnName, col.ColumnName);
                            }
                            bulk.WriteToServer(dt);
                        }

                        sql = @"
                            merge into HintText as target
                            using #HintText as source
                            on
                            (
                                target.CompanyCd = source.CompanyCd and target.Year = source.Year and target.QuestionCd = source.QuestionCd
                            )
                            when matched then
                                update set
                                    target.HintText = source.HintText,
                                    target.LastUpdateTime = source.LastUpdateTime
                            when not matched by target then
                                insert
                                (
                                    CompanyCd,
                                    Year,
                                    QuestionCd,
                                    HintText,
                                    LastUpdateTime
                                )
                                values
                                (
                                    source.CompanyCd,
                                    source.Year,
                                    source.QuestionCd,
                                    source.HintText,
                                    source.LastUpdateTime
                                );
                            ";
                        db.Database.ExecuteSqlCommand(sql);

                        sql = @"drop table if exists #HintText;";
                        db.Database.ExecuteSqlCommand(sql);

                        tran.Commit();
                    }
                    catch
                    {
                        tran?.Rollback();
                        throw;
                    }
                }

                return dt.Rows.Count;
            }
            catch (Exception ex)
            {
                errorProc err = new errorProc();
                err.ErrLog(this.ThisName(), ex);
                throw;
            }
        }
    }
}

        /// <summary>
        /// HintTextをCSV形式のファイルに変換します。
        /// </summary>
        /// <param name="viewModel"></param>
        /// <returns></returns>
        public FileContentResult Download(HintTextUploadViewModel viewModel)
        {
            try
            {
                using (var db = new dbModel())
                {
                    var hintTexts = db.HintText
                        .Where(h =>
                            h.CompanyCd == viewModel.CompanyCd &&
                            h.Year == viewModel.Year)
                        .OrderBy(h => h.QuestionCd)
                        .ToList();

                    var sb = new StringBuilder();

                    // ヘッダー
                    sb.AppendLine("QuestionCd,HintText");

                    foreach (var item in hintTexts)
                    {
                        sb.AppendLine(string.Join(",", item.QuestionCd, item.HintText.EscapeCsv(CrLfHandling.Keep)));
                    }

                    // UTF-8(BOM付き)
                    var encoding = new UTF8Encoding(true);
                    var bom = encoding.GetPreamble();
                    var body = encoding.GetBytes(sb.ToString());

                    var bytes = new byte[bom.Length + body.Length];
                    Buffer.BlockCopy(bom, 0, bytes, 0, bom.Length);
                    Buffer.BlockCopy(body, 0, bytes, bom.Length, body.Length);

                    return new FileContentResult(bytes, "text/csv; charset=utf-8")
                    {
                        FileDownloadName = $"HintText_{viewModel.Year}.csv"
                    };
                }
            }
            catch (Exception ex)
            {
                errorProc err = new errorProc();
                err.ErrLog(this.ThisName(), ex);
                throw;
            }
        }

        /// <summary>
        /// CSVファイルをHintTextテーブルにマージします。
        /// CSVのパース（DataTableへの変換）まではビジネスロジックとしてここで行い、
        /// DB固有の一括更新処理は <see cref="IHintTextBulkMergeRepository"/> に委譲します。
        /// </summary>
        /// <param name="viewModel"></param>
        /// <returns></returns>
        private int MergeHintCSV(HintTextUploadViewModel viewModel)
        {
            try
            {
                var dt = BuildHintTextDataTable(viewModel);

                if (dt.Rows.Count == 0)
                    return 0;

                return _bulkMergeRepository.Merge(dt);
            }

                throw;
            }
        }

        /// <summary>
        /// アップロードされたCSVファイルを読み取り、HintTextテーブルにマージ可能な
        /// DataTable（CompanyCd, Year, QuestionCd, HintText, LastUpdateTime）を組み立てます。
        /// </summary>
        /// <param name="viewModel"></param>
        /// <returns></returns>
        private DataTable BuildHintTextDataTable(HintTextUploadViewModel viewModel)
        {
            try
            {
                var now = DateTime.Now;
                var dt = new DataTable();
                dt.Columns.Add("CompanyCd", typeof(int));
                dt.Columns.Add("Year", typeof(int));
                dt.Columns.Add("QuestionCd", typeof(int));
                dt.Columns.Add("HintText", typeof(string));
                dt.Columns.Add("LastUpdateTime", typeof(DateTime));

                using (var sr = ReadCsvFile(viewModel))
                {
                    var headerFields = sr.ReadFields(); // ヘッダー行を読み飛ばす
                    while (!sr.EndOfData)
                    {
                        var fields = sr.ReadFields();
                        if (fields.Length < 2 || !int.TryParse(fields[0], out var questionCd)) continue;

                        var row = dt.NewRow();
                        row["CompanyCd"] = viewModel.CompanyCd;
                        row["Year"] = viewModel.Year;
                        row["QuestionCd"] = questionCd;
                        row["HintText"] = fields[1];
                        row["LastUpdateTime"] = now;
                        dt.Rows.Add(row);
                    }
                }

                return dt;
            }
            catch (Exception ex)
            {
                errorProc err = new errorProc();
                err.ErrLog(this.ThisName(), ex);
                throw;
            }
        }

        /// <summary>
        /// CSV読み込み
        /// </summary>
        /// <returns></returns>
        private TextFieldParser ReadCsvFile(HintTextUploadViewModel viewModel)
        {
            try
            {
                var encoding = EncodingDetector.DetectEncoding(viewModel.CsvFile.InputStream);
                var sr = new TextFieldParser(viewModel.CsvFile.InputStream, encoding) 
                {
                    TextFieldType = FieldType.Delimited,    // カンマ区切りの指定
                    HasFieldsEnclosedInQuotes = true,       // フィールドが引用符で囲まれている
                    TrimWhiteSpace = false                  // フィールドの空白トリム設定
                };

                sr.SetDelimiters(",");

                return sr;
            }
            catch (Exception ex)
            {
                errorProc err = new errorProc();
                err.ErrLog(this.ThisName(), ex);
                throw;
            }
        }

このコードは「コンストラクタチェーン（constructor chaining）」というC#の機能で、2つのコンストラクタを定義しています。

それぞれの役割

public HintTextUploadService() : this(new HintTextBulkMergeRepository()) { }

引数なしコンストラクタです。中身は空ですが、: this(...) の部分で「自分自身の別のコンストラクタを、指定した引数付きで先に呼び出す」という指示をしています。

public HintTextUploadService(IHintTextBulkMergeRepository bulkMergeRepository)
{
    _bulkMergeRepository = bulkMergeRepository;
}

本体のコンストラクタです。渡された IHintTextBulkMergeRepository を _bulkMergeRepository フィールドに保存する、実際の初期化処理です。

実行される順序

new HintTextUploadService()（引数なし）を呼んだ場合の流れはこうです。

  1. new HintTextBulkMergeRepository() で具象クラスのインスタンスを生成
  2. そのインスタンスを引数として、this(...) 経由で本体のコンストラクタを呼び出す
  3. 本体が実行され、_bulkMergeRepository にセットされる

なぜこう分けているか

  • 本体側を用意しておくことで、単体テスト時に new HintTextUploadService(mockRepo.Object) のようにモックを注入でき、実際のDBアクセスなしでビジネスロジックだけをテストできます。
  • 引数なし側を用意しているのは、既存のController側のコードが new HintTextUploadService() と呼んでいるためです。デフォルト実装を内部で渡すことで、既存の呼び出しコードは一切変更せずに済みます。
Controller側（既存コードのまま）
  new HintTextUploadService()
        │
        ▼
  HintTextUploadService()  ← 引数なし
        │  : this(new HintTextBulkMergeRepository())
        ▼
  HintTextUploadService(IHintTextBulkMergeRepository bulkMergeRepository)  ← 本体
        │
        ▼
  _bulkMergeRepository = bulkMergeRepository;  （本物のRepositoryがセットされる）


テストコード（新規）
  new HintTextUploadService(mockRepo.Object)
        │
        ▼
  本体を直接呼ぶ → _bulkMergeRepository = mockRepo.Object;  （モックがセットされる）

将来UnityやAutofacなどのDIコンテナを導入する場合は、コンテナが対応関係を管理してくれるため、この引数なしコンストラクタ自体が不要になる可能性もあります。現時点では「DIコンテナなしでもテスト容易性を確保する」ための実務的な折衷案です。
